# 飞书云端提醒中继模块 PRD

版本：v0.7.2-cloud-feishu-dedup
状态：v0.7.2 已部署；SQLite/日志实查、异常状态修复、云端状态机回归和公网健康检查已通过
关联模块：[待办与提醒](../02-待办与提醒/PRD.md)、[设置与主题](../05-设置与主题/PRD.md)

## 1. 目标与边界

- 手机继续负责读取 WebDAV、解析 Obsidian 待办、建立本地 `AlarmManager` 提醒。
- 手机成功同步后，上报当前远程待办的提醒快照。
- 云主机不读取 WebDAV，只保存提醒状态并在到点调用飞书机器人 Webhook。
- 手机上报成功后即使关机或断网，云端仍按保存的时间发送飞书；手机本地通知仍由手机自身负责。
- 手机从未成功同步上报时，云端无法提前知道任务新建、修改、完成或删除；取消云端提醒依赖下一次成功同步。

## 2. App 开关与发送边界

设置页提供“云端飞书提醒（手机离线也可推送）”开关，默认打开并持久化。

- 关闭时，手机向云端提交空快照取消本设备全部云端提醒；网络失败必须明确提示，不能伪称已取消。
- 开关只控制云端中继，不关闭手机本地提醒。
- 打开时，手机不直接调用飞书 Webhook；云端登记失败只报告状态，不回退为手机直发。
- 关闭后恢复现有手机直发飞书链路。
- 开关打开期间，以最新完整云端快照作为任务状态来源。

## 3. 上报协议

使用 HTTPS；请求携带独立设备 Token，不上传 WebDAV 密码或飞书 Webhook。

接口：

```text
POST /v1/reminders/reconcile
```

请求至少包含：

- `device_id`
- 完整 `observed_task_ids`
- 当前可调度提醒列表

每项至少包含：

- 稳定 `task_id`
- 任务正文
- 来源路径
- 提醒时间的 Unix 毫秒值
- IANA 时区

服务规则：

- 以 `(device_id, task_id)` 幂等更新。
- 提醒时间变化时重置发送状态；重复快照不得重复推送。
- 完成、删除、移出同步范围、取消提醒的任务不进入 active 列表，云端必须取消其调度。
- 云端返回明确成功/失败；手机记录最近一次云端同步时间和结果。
- 云端失败不影响 WebDAV 同步和手机本地提醒。

## 4. 云端职责与安全

- 使用 SQLite 或同等持久化存储，保存任务、时间、时区、发送状态、重试次数和最后错误。
- 到点发送结构化飞书卡片；HTTP 非 2xx、业务码非 0 或网络异常按指数退避重试，并设置最终失败状态。
- 只监听独立服务端口，不修改已有 OpenClaw/Caddy/FRP 服务。
- 日志不得记录设备 Token、Webhook 或完整任务正文。
- 飞书 Webhook 只放在云端环境变量或权限为 0600 的配置文件中。
- APK 只包含云端 API 地址、设备 Token 和服务证书指纹；禁止把 WebDAV 密码写入 APK 或云端源码。
- 当前只有公网 IP 时使用证书指纹固定；获得域名后迁移到标准 CA 证书。

## 5. 调度门闩与失败语义

- 云端工作线程只能发送 `remind_at` 已到达的任务；同步刚写入未来提醒时不得立即推送。
- 同一任务连续同步 3 次只保留一条云端提醒。
- 修改提醒时间时，旧时间不得发送，新时间重新进入调度。
- 云端重启后尚未领取的任务不得丢失；已处于 `sending` 的在途任务不得被自动回收重发。
- 可确认的发送失败按退避重试；发送结果不确定时不得自动重发，避免重复消息，最终状态必须可诊断。
- 成功和明确失败的状态变更必须显式提交 SQLite 事务；不得把“进程内执行过 UPDATE”误判为“状态已持久化”。
- 本地提醒和 WebDAV 同步独立于云端状态，云端故障不能阻塞用户输入。

## 6. 验收标准

- 手机成功同步并收到云端 ACK 后断网/关机，到点仍发送一条飞书卡片。
- 同一任务重复同步不重复发送；修改时间只发送新时间。
- 完成、删除、取消提醒后下一次同步能取消云端调度；关闭开关能清理本设备任务。
- 云端重启后未领取提醒不丢失；在途发送不因重启或 10 分钟租约回收而重复。
- 手机本地提醒、Obsidian WebDAV 同步仍可用。
- 开关关闭时手机直发可用，开关打开时飞书发送完全由云端负责。
- 卡片显示待办内容、提醒时间和来源“大尾巴闪念.手机端”，日志和测试输出不泄露敏感配置。
- 真实手机联测必须记录设备、包信息、上报响应、云端状态、到点结果和失败/取消结果；当前设备不在线时保持待补验状态。

## 7. v0.7.2 线上修复证据（2026-08-08）

- 云主机日志确认同一任务从 15:00 起每 10 分钟成功投递；SQLite 唯一异常记录为 `sending / attempts=49 / sent_at=NULL`。

- 部署前已备份线上服务代码与 SQLite；部署后代码哈希已变化，10 分钟回收逻辑不存在，成功/失败路径各包含显式 `commit()`。
- 异常记录已归一为 `sent / attempts=49`；服务恢复后公网 `/healthz` 返回 HTTP 200，23:10 未出现原定下一轮 `reminder sent` 日志。
